1 / FOUNDATION

What is OMNI?

OMNI is a browser-based modular instrument designer. You build a sound system from modules, connect their inputs and outputs, then play the result through the built-in keyboard or a MIDI controller.

The instrument has two linked workspaces. Engine View is where sound is created: modules live on a patch canvas and connections define how audio, control signals and note events move through the instrument. Front-end View is where you design the control panel that a player will use. Its controls can be bound to the same modules and parameters in the engine.

One engine, two ways to work. Front-end View does not create a second audio graph. A bound knob, slider, switch or drawbar writes to its selected engine parameter, while keyboards, wheels and pads use OMNI's existing performance APIs.

OMNI opens in Engine View by default. You can switch workspaces from the centred selector in the editor's top bar. Audio does not start automatically; press POWER ON when you are ready to play.

2 / FIRST PATCH

Quick start

The fastest way to understand the signal flow is to open a template, power on the engine, and follow the connections from the keyboard to the output.

  1. Open a starting point.From the OMNI launcher, choose Templates and open a patch. Choose New Patch to start with the default instrument, or open Empty Canvas to build from an output module.
  2. Add or move modules.In Engine View, click a module in the searchable library to add it, or drag it onto the canvas. Drag a module by its header to move it.
  3. Connect the signal path.Drag from an output port on the right side of a module to a compatible input on another module. The port colours indicate the signal type.
  4. Power on and play.Press POWER ON in the performance pane. Play the on-screen keyboard, use the computer-keyboard note layout, or connect a MIDI controller.
  5. Save your work.Use File → Save patch… to save to this browser. Export a JSON patch file when you need a portable backup.

3 / SOUND DESIGN

Engine View

Engine View is a patch canvas: each module performs one job, and the connections between modules form the instrument.

Module library

Use the search field to filter the module list by name. Click a module to add it near the current canvas view, or drag it onto a specific position. Select a module on the canvas to open its parameters in the inspector. Each module also has an information control that opens its technical reference.

Canvas navigation

Drag empty canvas space to pan and scroll to zoom. Use View → Zoom in, Zoom out or Fit patch to canvas when you need a specific view. The grid snap control can be turned on or off.

Select and edit

Click a module to select it. Shift-click adds or removes modules from the selection; Shift-drag on empty canvas draws a selection box. Drag the header of a selected module to move the group. Use the Edit menu to undo, redo, select all, copy, paste, duplicate or delete.

Module parameters can be changed in the inspector. Numeric controls update the live graph while audio is running. Structural edits update the graph connections and affected modules.

Top-bar menus

File

Create a patch, open templates, save or load a saved patch, import or export patch JSON, and export an SVG schematic.

Edit

Undo and redo, manage selections, copy, paste, duplicate and delete modules or front-panel controls.

View

Zoom, fit the canvas, toggle grid snapping, and show or hide the performance pane.

Audio / MIDI

Record audio or MIDI, stop held notes, request MIDI access and open MIDI assignments.

Help

Open the in-app guide and keyboard-shortcut reference. Front-end View also provides its studio guide and design check.

4 / BUILDING BLOCKS

Module catalogue

The current engine defines 56 module types. The groups below organise them by what they do; they are a reference for the available building blocks, not a required order for wiring a patch.

Performance & note tools

Keyboard & MIDI; Step Sequencer; Clock / Trigger; Euclidean Rhythm; Random Melody; Arpeggiator; Chord Generator (2–8 voices); Note Transpose / Velocity; Note Echo.

Sound sources

Oscillator; Noise Generator; Sub Oscillator; Supersaw; Additive Oscillator; Plucked String; Drum Voice; 2-Op FM; TR-808 Bass Drum; TR-808 Snare Drum.

Instrument-derived voices

DX7 FM Voice; SEM Poly Synth; Mellotron Tape Voice; OB-Xa Poly Voice; Pro 3 Wavetable Oscillator; Super 8 Binaural Voice; Nord Tonewheel Organ; Clavinet D6 Voice.

Filters & effects

Filter; Moog Ladder Filter; MS-20 Dual Filter; Juno Chorus; Delay / Echo; Reverb; Distortion; Bitcrusher; Compressor; 3-Band EQ; Ring Modulator; Formant Filter; Stereo Panner; Phaser; Tremolo; Comb Resonator; Stereo Widener.

Mixing & amplification

Instrument-derived modules are Overture's software implementations and models. Their names describe the instrument or circuit ideas they draw from; they are not licensed copies of proprietary firmware, factory banks or hardware designs.

5 / ROUTING

Connections & signal types

A connection carries one kind of information from a module output to a compatible module input. Matching the port type is as important as choosing the right module.

SignalColourWhat it carriesTypical use
AudioAMBERSound flowing through the instrument.Oscillator → filter → VCA → effects → output.
CVCYANContinuous control values.Envelope or LFO → filter cutoff, pitch modulation or amplifier gain.
NoteGREENNote events, including pitch, velocity and gate state.Keyboard or sequencer → oscillator, drum voice or envelope.

Making a connection

  • Drag from an output port to a compatible input port. The editor highlights valid destinations as you connect.
  • You can also click an output port, then click one of its highlighted compatible inputs.
  • To remove a wire, select it and press Delete or Backspace.
Think in signal paths. A sound source usually needs a route to Audio Output. A keyboard or sequencer sends note events to a playable voice; envelopes often receive the same note or gate event so they can shape amplitude or filter movement.

OMNI checks port compatibility and prevents unsupported audio/CV feedback loops. If a connection is rejected, check that the output and input are intended for the same signal type.

6 / PLAYING

Performance & MIDI

The performance pane gives you a keyboard and real-time controls for playing the current patch without adding a separate instrument or audio graph.

Built-in keyboard

The performance keyboard spans five octaves, C2–C7. Use the octave − / + buttons to transpose its playing range. Computer-keyboard notes are also available.

Voice mode

Choose MONO or POLY in the performance controls. The keyboard module also exposes its voice-mode parameter in Engine View.

Pitch & modulation

The pitch wheel bends the played notes. The mod wheel sends modulation to modules that respond to it. Both can be controlled from the interface or a mapped MIDI controller.

Master & panic

Adjust MASTER for the output level. PANIC sends all-notes-off behaviour to release notes that remain held.

Connecting a MIDI controller

  1. Connect your controller and open MIDI → Request MIDI access.
  2. Grant the browser's MIDI permission when prompted. The MIDI status area reports whether a device is connected.
  3. Open MIDI → MIDI assignments… or the MIDI MAP button to assign controller messages to supported controls.
  4. Move a mapped hardware control and confirm that its target changes. You can edit or clear assignments in the MIDI map.

Web MIDI support and device access depend on the browser and its permissions. If a controller is not listed, check the browser's MIDI permission and reconnect the device before requesting access again.

To make more room for the patch, use View → Hide Performance Pane. Choose Show Performance Pane to bring it back.

7 / CAPTURE & CONTROL

Recording & macros

Audio recording

Choose Audio → Record audio… to capture the live master output. Start audio first with POWER ON, begin recording, then stop the recording from the same menu. OMNI downloads a browser-supported audio recording. The available container and codec depend on the browser.

MIDI recording

Choose Audio → Record MIDI… to capture performance events as a Standard MIDI File. The recorder receives note events from the live graph, including notes produced by keyboards, sequencers, clocks, arpeggiators, chord generators and note-processing modules. Incoming MIDI control data can include CC, pitch bend, channel aftertouch, polyphonic aftertouch and program changes.

Stop the recording from the same menu to export the MIDI file. Notes that remain held are closed when recording stops.

Macros

Macros provide a single control for several numeric module parameters. A macro can be assigned to a MIDI CC so one hardware control can move several related values together. Use them for linked changes such as filter, effect and modulation amounts.

8 / LIBRARY

Patches, templates & sharing

Start from a template

Templates are complete example patches with modules, connections and starting parameter values. Open them from the launcher with TEMPLATES, or from File → Templates… inside Engine View. They are starting points; change any module or connection after opening.

Save locally

Use File → Save patch… to save the current instrument in this browser. Use the saved-patch selector in the File menu to reopen a local save. Browser-local patches are tied to the current browser profile and storage; export a JSON backup before clearing browser data or moving to another device.

Import and export

  • Export patch JSON saves the complete patch data, including its optional front-panel layout.
  • Import patch JSON loads a compatible OMNI patch file into the editor.
  • Export SVG schematic produces a vector diagram of the Engine View module graph.
  • Export library from the launcher backs up the patches currently shown in the library.

Account and Community patches

The launcher can show saves from this device, private account patches and published Community patches together. Sign in to your Overture account to use account sync and private cloud saves. Published patches are shared through the Community library and remain separate from private account saves.

9 / INSTRUMENT DESIGN

Front-end View

Front-end View is a visual studio for designing the panel a player will interact with. It is stored as part of the patch, so the front panel can travel with the sound engine.

The three working areas

  • Component library: search and browse visual controls. Click an item to insert it, or drag it onto the faceplate.
  • Faceplate canvas: position and resize controls, arrange layers and use layout guides.
  • Inspector and layers: edit a component's Layout, Appearance and Behaviour settings; control visibility, locking and stacking order in the layer list.

Available components

The palette includes knobs, rotary encoders, sliders, dropdowns, buttons, switches, drawbars, keyboards, pitch and modulation wheels, performance pads, meters, LEDs, LCD/OLED displays, module bays, text labels and section dividers. Knobs and rotary encoders are separate control types; the duplicate Dial option is not used.

Bind a control to the engine

  1. Select a component on the faceplate.
  2. Open the Behaviour area of the inspector.
  3. Choose an OMNI module first, then choose one of that module's compatible parameters.
  4. Check the parameter range and LIVE state, then move the control while audio is running to confirm that the engine responds.

Unbound visual parts do not change the sound. The panel uses the existing patch and live parameter API; it does not create another audio engine.

Layout & appearance

Layout controls position and dimensions. Appearance controls surface and accent colours, legends, borders, materials, spacing, padding, corner radius, border thickness and shadow. Panel-level settings define the faceplate dimensions, finish, frame and global colours. Hardware palettes provide coordinated starting combinations, and individual colours remain editable.

Arrange the faceplate

Use multi-selection to move or edit a group. The Arrange menu provides alignment, distribution and matched dimensions. The layer stack can hide, lock or reorder components. Rulers, grid snapping, guides, safe margins and measurements help with placement; these are editing aids rather than exported faceplate elements.

10 / REVIEW & DELIVERY

Preview, design check & export

Navigate the faceplate canvas

Choose the Pan tool in the View group to drag the canvas, even when the pointer starts over a component. You can also drag blank canvas space, hold Space while dragging, or use the middle mouse button. Ctrl/⌘+wheel and the zoom controls zoom the faceplate. Use Fit to return the whole panel to the workspace.

Test the live panel

Choose Test or TEST PANEL to temporarily pause layout editing and interact with the live keyboard, wheels, pads and bound controls. Exit test mode to edit the design again.

Design Check

Design Check reports components outside the faceplate, controls that are very small, missing labels, invalid or missing engine bindings, and likely overlaps. Review its findings, then adjust the affected controls. It checks layout and bindings; it does not test audio quality or every screen size.

Preview and export formats

FormatWhat it contains
SVGScalable vector artwork of the faceplate.
PNGRaster faceplate image at 1×, 2× or 3×.
JPEGFlattened raster faceplate image at 1× or 2×.
Front-panel JSONEditable panel-only layout that can be imported into another patch.
Print sheet / PDFOpens a browser print layout. Choose “Save as PDF” in the print dialog.

The Preview window renders the faceplate inline. Rulers, grids, guides, measurements, safe margins, selections and editor handles are not part of the exported artwork.

CAD note SVG is the current vector interchange format. Native CAD/B-rep export, constraint solving and manufacturer-ready mechanical drawings are not implemented.

Performance Report

The report shows total, visible and hidden component counts, per-type counts, SVG source size and the time spent on the most recent synchronous DOM build. That timing is not audio latency, browser paint time or end-to-end interaction latency.

12 / HELP

Troubleshooting & common questions

Why is there no sound?

Press POWER ON to start the audio engine. Then check that a note source reaches a playable voice, that the voice's audio output has a path to Audio Output, and that the output level is not at zero. A voice may also need a gate or envelope connection to open its amplifier.

Why can't I connect two ports?

The two ports may carry different signal types, or the connection may create an unsupported feedback loop. Try another compatible input and check the port colours: amber for audio, cyan for CV and green for note events.

Why is my MIDI controller not listed?

Check that the browser supports Web MIDI, that the page has permission, and that the controller is connected. Use MIDI → Request MIDI access to refresh the connection status.

Why doesn't a front-panel control change the sound?

Visual controls are not automatically connected to the engine. Select the component and bind it in Behaviour by choosing a module and one of its compatible parameters. Keyboard, wheel and pad components use the shared performance engine.

Why didn't my printed PDF appear?

The print sheet opens in a new browser window. Allow pop-ups for the site, then use the browser's print dialog and choose “Save as PDF”.

Can I export the faceplate as a CAD model?

Not currently. Export SVG for vector artwork, or use the editable panel JSON to preserve the layout. SVG is not a 3D CAD model.

Does OMNI save my patches to my account automatically?

Browser-local saves stay in the current browser profile. Sign in from the launcher to use account and Community patch features, and keep a JSON export when you need a portable backup.
